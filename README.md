## 📦 Опис модулів

### 1. `core_api_connector` (Завершено)

Модуль надає кастомний асинхронний REST API інтерфейс для зовнішніх інтеграцій (веб-сайтів, мобільних додатків, CRM-систем та зовнішніх сервісів) без прямого доступу до бази даних Odoo.

#### Ключові можливості:
* **Авторизація:** Захист ендпоінтів за допомогою унікальних API-ключів через заголовок `X-API-KEY`.
* **Управління лідами (CRM):** Прийом та валідація вхідних завок, автоматичне перевірка і створення/зв'язування контрагентів (`res.partner`) та лідів (`crm.lead`).
* **Каталог товарів:** Отримання списку номенклатури, цінових категорій та залишків товарів у реальному часі.
* **Обробка замовлень:** Прийом та реєстрація замовлень покупців (`sale.order`) з валідацією позицій, цін і типів доставки.
* **Асинхронні задачі (Celery):** Підтримка фонової обробки важких запитів для збереження високої швидкодії API.

### 2. `nova_poshta_connector` (Завершено)

Модуль для автоматизації логістичних процесів Нової Пошти безпосередньо із замовлень покупців (`sale.order`) в Odoo 19.

#### Ключові можливості:
* **Довідники:** Повна синхронізація міст (`nova.poshta.city`) та складів/поштоматів (`nova.poshta.warehouse`) через офіційне API v2.0.
* **Централізовані налаштування:** Вибір API Key та фіксованої точки відвантаження відправника (**Sender City** та **Sender Warehouse**) у меню `Settings -> Nova Poshta`.
* **Авто-реєстрація покупців:** Очищення та валідація українських номерів телефонів (формат `380...`), нормалізація імен та автоматичне створення контрагента-отримувача в системі Нової Пошти.
* **Генерація ТТН:** Створення Експрес-накладної у 1 клік прямо із форми `Sales Order` з автоматичним розрахунком ваги та вартості.
* **Анулювання ТТН:** Скасування та видалення накладної (`InternetDocument/delete`) із бази Нової Пошти та Odoo з можливістю повторної генерації.

### 3. `telegram_connector` (Завершено)

Модуль для автоматичної відправки оперативних сповіщень про бізнес-події з Odoo 19 у чати Telegram через REST API.

#### Ключові можливості:
* **Централізовані налаштування:** Кастомна панель у меню `Settings -> Telegram Integration` для збереження `Bot Token` та `Default Chat ID` у системних параметрах (`ir.config_parameter`).
* **Ізольований сервіс:** Модульна `AbstractModel` (`telegram.service`) з підтримкою форматирування HTML та обробкою помилок мережі для універсальної відправки повідомлень з будь-якої точки Odoo.
* **Сповіщення про замовлення (Sales):** Перехоплення підтвердження заказа покупця (`sale.order` -> `action_confirm`) з форматированием та миттєвою відправкою структурованої картки замовлення (номер, клієнт, сума, позиції).
* **Алерти складських залишків (Inventory):** Перевірка залишків товарів при проведенні відгрузки со склада (`stock.picking` -> `button_validate`) та автоматичне попередження в чат, якщо доступна кількість впала нижче порогу (`<= 5.0`).

### 4. `telephony_connector` (Завершено)

Модуль для интеграции с IP-АТС (Binotel/Ringostat/Phonopy), ведения истории звонков и автоматизации CRM при пропущенных вызовах.

#### Ключові можливості:
* **Webhook Endpoint (`/telephony/webhook/event`):** Публічний контролер (Odoo 19 `type='jsonrpc'`) для прийому подій про дзвінки у реальному часі.
* **Автоматичний пошук та нормалізація:** Очищення вхідних номерів телефонів та гнучкий пошук контрагента (`res.partner`) за останніми цифрами з авто-створенням нових контактів.
* **Журнал викликів (`telephony.call`):** Фіксація типу виклику (вхідний/вихідний/пропущений), тривалості, посилань на аудіозаписи та прив'язка до клієнта.
* **CRM Автоматизація:** Автоматичне створення Ліда (`crm.lead`) при пропущеному виклику для оперативного реагування відділу продажів.
* **Централізовані налаштування:** Кастомна панель у `Settings -> Telephony Integration` для керування секретними токенами та правилами автоматизації.

### 5. `stock_sync_connector` (Завершено)

Модуль синхронизации складских остатков и импорта заказов с маркетплейсов (Prom.ua, Rozetka) с поддержкой Sandbox/Mock режима.

#### Ключевые возможности:
* **Mock / Sandbox Mode:** Возможность тестирования всех процессов интеграции без реальных API-ключей маркетплейсов.
* **Экспорт остатков:** Автоматический и ручной расчет доступного количества (`qty_available`) и отправка на маркетплейс по SKU.
* **Импорт заказов (`/marketplace/webhook/order`):** JSON-RPC эндпоинт для авто-создания Заказов покупателей (`sale.order`) и контрагентов.
* **Журналирование (`marketplace.log`):** Подробный аудит всех попыток синхронизации остатков с сохранением полных ответов API.
